O desafio

O que foi pedido

A tarefa

  • Pegar uma aplicação pronta e colocá-la no ar em três nuvens diferentes
  • Usar a mesma receita de instalação nas três
  • Comparar preço, facilidade e trabalho de manutenção

A aplicação: um sistema de biblioteca

  • Feita em Java, com tela de login, cadastro de livros e de autores
  • Guarda os dados apenas na memória: cada reinício zera tudo
  • Por isso a instalação é demonstrativa e roda com uma cópia só

A regra: escolher dois provedores grandes (aqui, Amazon e Microsoft) e um terceiro menor (aqui, Hetzner).

A estratégia

Uma caixa, montada uma vez

Como a aplicação chega ao usuário

  1. Uma pessoa abre um endereço de internet no navegador
  2. A nuvem recebe o acesso e encaminha para a aplicação
  3. A aplicação responde com as páginas da biblioteca

Por que "montar uma vez"

  • A aplicação é empacotada numa caixa fechada, com tudo que precisa para funcionar
  • Essa mesma caixa é enviada, sem mudanças, para as três nuvens
  • A caixa roda sem permissões de administrador, por segurança

Montar uma vez, usar nos três lugares.

A configuração

Três partes para o Kubernetes

A senha secreta

A aplicação precisa de uma chave para gerar logins. Ela fica guardada num cofre do Kubernetes, nunca junto do código.

A aplicação

Quantas cópias rodar (uma), quanta memória usar e como o Kubernetes verifica, sozinho, se ela está saudável.

A porta de entrada muda por nuvem

Como a aplicação fica acessível de fora. É a única parte que muda de uma nuvem para outra.

Como foi na prática, na Microsoft (Azure)

Passo a passo em uma nuvem

  1. Criar uma área de trabalho na conta da Azure
  2. Enviar a caixa da aplicação para o repositório da Azure
  3. Pedir para a Azure criar o cluster (o Kubernetes já pronto para usar)
  4. Conectar a ferramenta do computador a esse cluster
  5. Enviar as três partes da configuração
  6. A Azure devolve um endereço de internet. Abrimos, fizemos login, funcionou

Na Amazon o caminho é parecido, só com nomes diferentes. Na Hetzner, nós mesmos instalamos o Kubernetes num servidor.

Recomendação

Nossa escolha: Hetzner

  • Custa cerca de 38 vezes menos que a Amazon, no mesmo cenário
  • O servidor mais simples já dá conta desta aplicação com folga
  • Os recursos avançados das nuvens grandes não ajudam aqui: a aplicação roda com uma cópia só e não guarda dados

Se fosse um sistema de verdade: Azure

Melhor equilíbrio entre custo e facilidade, com o Kubernetes já pronto e a limpeza em um comando.

Amazon

Vale a pena quando a empresa já usa a Amazon para tudo, mesmo custando mais.
